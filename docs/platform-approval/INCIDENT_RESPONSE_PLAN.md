# INCIDENT_RESPONSE_PLAN

## 1. 范围

适用于：凭据泄露、未授权访问、数据泄露、平台 API 滥用、Kill Switch 触发、跨租户隔离失效、资金/账本一致性异常。

## 2. 分级

| 级别 | 定义 | 目标响应 |
| --- | --- | --- |
| SEV-1 | 凭据泄露 / 跨租户数据暴露 / 账本不一致 | 立即：停用凭据 + Kill Switch + 1 小时内通报宿主与（如适用）平台 |
| SEV-2 | 单租户数据异常 / 同步错误导致错误事实 | 4 小时内定位 + 修复 + 审计留痕 |
| SEV-3 | 功能异常、无数据影响 | 下个工作日处理 |

## 3. 处置流程

1. **发现**：监控/告警/客户报告 → 记录时间线；
2. **遏制**：撤销 OAuth token、停用连接、必要时触发 Kill Switch；
3. **取证**：只读导出相关审计记录（不得修改原始事实）；
4. **修复**：修复根因，补测试（永久回归基线）；
5. **通报**：按平台与法规要求通报（**HOST 决定对外通报**）；
6. **复盘**：更新本计划与 `SECURITY_CONTROLS_EVIDENCE.md`。

## 4. 联系与责任

| 角色 | 责任 | 状态 |
| --- | --- | --- |
| Security contact（对外） | 平台填写、安全联系 | **HOST 提供** |
| Incident commander | 现场指挥与升级 | Codex 执行技术处置，宿主决策对外动作 |
| 平台联络人 | 按平台要求通报 | **HOST** |

> 平台申请通常要求提供 Emergency/Security contact 与可证明的 IR 流程；本文件为草案，实施批次需补齐演练记录。
