# PRIVACY_DATA_LIFECYCLE

> 任何「永久保存所有原始数据」的默认设计都需要审查。

| # | 问题 | 当前答复（2026-10-01） |
| --- | --- | --- |
| 1 | 客户授权了什么？ | 平台官方 OAuth/商户授权，仅限 READ + 最小 scope（见各 `*_SCOPE_MATRIX.md`） |
| 2 | 为什么需要？ | 仅用于 Recovery detection / Evidence / Settlement reconciliation / Fee discrepancy / Logistics recovery / Chargeback·dispute recovery / Recovery tracking |
| 3 | 存在哪里？ | 生产数据库（CanonicalFact / Evidence 元数据）+ 对象存储（证据文件）；凭据仅存 Secret Manager |
| 4 | 加密方式？ | in transit：强制 TLS；at rest：依赖生产加密配置（`HOST`） |
| 5 | 谁能访问？ | 租户内被授权角色（RBAC + Membership），跨租户一律拒绝；运维访问需最小化并留痕 |
| 6 | 是否进入 AI？ | 仅进入受控 AI 处理（抽取/解释/草稿），**不决定**金额/Fee/Deadline/Ledger/Settlement；进入前剥离直接标识 |
| 7 | 是否进入日志？ | 结构化日志**不含**凭据值、不含直接标识；错误信息不得回显敏感值 |
| 8 | 保存多久？ | 按「业务事实必要期 + 合规留存要求」定义；原始报文有明确 TTL，超期删除或匿名化 |
| 9 | 什么时候删除？ | 达到 TTL / 客户删除请求 / 授权撤回 / App 卸载 → 触发删除或匿名化流程 |
| 10 | 客户撤销授权后怎么办？ | 立即停止同步；按策略删除或匿名化原始数据；保留必要的审计/财务记录（去标识化） |
| 11 | 卸载 App 后怎么办？ | 同 10；连接进入 `DISCONNECTED`，不再发起任何读取 |
| 12 | 删除账户后怎么办？ | 触发租户级删除流程；审计与财务最小留存按合规要求保留并去标识化 |
| 13 | 审计/财务数据哪些必须保留？ | 追回事实、审批、结算与账本记录按合规留存；保留的是**记录**，不是原始 PII |
| 14 | PII 如何删除或匿名化？ | 直接标识字段不采集（V1）；如已采集 → 不可逆匿名化或删除，并记录执行证据 |
| 15 | 备份中的数据多久过期？ | 备份保留窗口需明确定义并记录；恢复演练需说明备份内数据同样受删除策略约束 |
| 16 | 第三方处理商有哪些？ | 云/数据库/对象存储/监控/邮件等；需列出并签署 DPA（`HOST` 法务确认） |

## 默认原则

- **最小采集**：不参与 Recovery 的字段默认不申请（尤其直接标识）。
- **分离**：CrossClaim 自身计费的 Stripe Billing 与客户业务 PSP 数据严格分离。
- **可执行**：每条保留/删除策略必须在实施批次中变成可执行任务 + 证据（不能只写文档）。
